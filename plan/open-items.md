# Road Trip Planner: Open Items

This document lists what's still open and has no phase to settle it: questions nobody has a plan for yet, things to check, and ideas set aside. A question that a phase will answer goes in that phase's open questions, in the [development plan](development-plan.md), not here.

**How to use it:**

- **Add an item as soon as something is set aside,** in chat or during a phase. Give it the next number, and say where it came from.
- **Numbers never change.** Other docs and PRs refer to an item by its number, such as "open item 3."
- **When an item is settled, or a phase takes it on,** strike it through and add a line saying when and how, such as "**Moved 2026-11-02:** to phase 29's open questions." Write any decision into the design doc it belongs to. Struck items stay in the list.

| 15 | **Review text can still close the `place_content` label.** `labeledAsPlaceContent()` removes the closing tag in one pass, so `"a</place_</place_content>content> b"` becomes `"a</place_content> b"`. | 17 | **A day with no start or end place still gets a drive.** `Calendar.#hasDrives()` leaves out the "both ends are known" rule in domain model 4.7. On a new trip, `scheduleOf()` returns one drive with no times. | Code review evaluation, PR #32 |
| 18 | **Saving places from a search can wait on a write.** Persistence design section 4 says "Saving places from a search takes no lock, so workers' searches never wait." But `places.trip_id` has a foreign key to `trips`, so each place insert briefly locks the trip row. That lock waits behind the `FOR UPDATE` lock a write holds, which can last seconds once a write makes Google calls. Two place saves that insert the same new places in opposite order can also deadlock, and Postgres aborts one. Fix the code or the design line. | Code review evaluation, PR #30 |
| 19 | **A route that starts and ends at the same place.** A loop trip's last day before any stays exist (home to home), or a stay-put day whose only stop is the hotel, sends Routes a call with the same start and end. The schema in `src/google/routes.schema.ts` requires `encodedPolyline`. If Google leaves it out for a zero-length route, or answers `{}`, the write fails. One real call to Google would settle it. | Code review evaluation, PR #34 |
| 20 | **Moving the start place can start the trip early.** The start date is checked against "today" only when it's set (`setStartDate`), and "today" follows the start place's time zone. If the user moves the start place to a time zone further east late on the night before the start date, the trip can start right away, and the started-trip lock then refuses changes to the plan. Rare, but costly when it happens. It may need a check when the start place changes (domain model 3.4). | Code review evaluation, PR #33 |
